# Runtime behaviour (src)

- **main.ts:** `NestFactory.create<NestExpressApplication>(AppModule, { bufferLogs: true })`, `app.disable('x-powered-by')` (no `X-Powered-By: Express` header), `app.set('trust proxy', …)` only when `TRUST_PROXY` is set (`parseTrustProxy`), `app.useLogger(pino Logger)`, global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })`, global `GlobalExceptionFilter(logger)`, `enableCors({ origin: parseOrigins(CORS_ORIGIN), credentials: true })` (credentials for the session cookie; origins stay an explicit list), `enableShutdownHooks()`, Swagger at `/docs` when enabled, with cookie auth and the CSRF `requestInterceptor` (see `api-docs.md`), listen on `PORT ?? 3000`. Tests that build the app from `AppModule` don't run `main.ts`, so they get none of these (but do get the middleware and guards below).
- **AppModule:** the first line is `import './common/bigint-json.js'`, which makes BigInt serialise to JSON as a **string**. It imports `ConfigModule.forRoot({ isGlobal: true })`, `ThrottlerModule.forRoot([{ ttl: 60_000, limit: 100 }])`, `LoggerModule`, `PrismaModule`, `SessionsModule`, `UsersModule`, `MetricsModule`, `AuthModule`, `HealthModule`, `TicketsModule`, the monitoring modules, `RolesModule` and `PermissionsModule`. It registers the **global guards in order: `ThrottlerGuard` → `AuthGuard` → `CsrfGuard` → `PermissionsGuard`**. It applies **middleware to `'*'` in order: `RequestIdMiddleware` → `OriginCheckMiddleware` → `SessionMiddleware`** (see `auth.md`).
- **SessionMiddleware** (`src/sessions/session.middleware.ts`): `express-session` (cookie `ctd.sid`, `resave: false`, `saveUninitialized: false`, `rolling` only with an idle timeout) on `PrismaSessionStore`. It skips `/health`, `/ready` and `/metrics`, so probes never touch the session table. It awaits the session load and turns a failure into an exception, so `GlobalExceptionFilter` answers it (a plain `next(err)` would reach Express's default error page). Store failures after the response (touch) are logged by the store, not raised.
- **OriginCheckMiddleware** (`src/common/middleware/origin-check.middleware.ts`): POST/PATCH/PUT/DELETE with an `Origin` that is neither in `CORS_ORIGIN` nor the request's own host → 403 "Origin not allowed"; no `Origin` → allowed.
- **RequestIdMiddleware** (`src/common/middleware/request-id.middleware.ts`): reuses the incoming `x-request-id` header (as-is, not validated) or generates `randomUUID()`, sets `req.requestId`, and returns the `X-Request-ID` response header. pino-http separately assigns its own `req.id`, a per-process counter (1, 2, 3…), so log lines carry both. The user chose to keep this original setup (2026-10-06) after trying a single-id version.
- **GlobalExceptionFilter** (`@Catch()` for everything): logs `{ err, requestId, method, url, statusCode }`. Status ≥ 500 logs at `error` ("Unhandled exception"); 4xx logs at `warn` ("Request rejected"). It responds with `{ statusCode, message }`. The message is `"Service unavailable"` for 503 (e.g. a failed readiness check), `"Internal server error"` for any other 5xx or non-HttpException, and `exception.message` for 4xx. 5xx bodies never include details. Note that validation error *details* (the message array) are not returned, only "Bad Request Exception".
- **LoggerModule:** pino-http level `LOG_LEVEL ?? 'info'`, default serializers, so request and response are logged in full (all headers, query, params, remote address/port, response headers). Uses pino-pretty (colorize, singleLine, `SYS:standard`) when `NODE_ENV !== 'production'`. Redacts `req.headers.authorization`, `req.headers.cookie`, `req.headers["x-csrf-token"]`, `res.headers["set-cookie"]` (the session cookie at login), `password`, `token`, `accessToken` and `refreshToken` as `[REDACTED]`.
- **MetricsModule:** `PrometheusModule.register({ path: '/metrics', controller: MetricsController })`. `MetricsController` extends `PrometheusController` and is `@Public()` and `@SkipThrottle()`, so Prometheus can scrape without logging in. Restrict it at the network or proxy level when deployed.
- **PrismaModule** is `@Global()`, so it provides and exports `PrismaService` everywhere. **PrismaService** extends `PrismaClient`, and its constructor builds `PrismaPg({ connectionString: DATABASE_URL }, { schema: DB_SCHEMA })` where `DB_SCHEMA = 'ctd_config'`. It calls `$connect()` on init and `$disconnect()` on destroy.
- **ParseBigIntPipe** (`src/common/pipes/`): turns a `:id` param into `bigint` and returns 400 for anything that isn't digits only.

## Prisma client usage pattern (working example: seed.ts / import-tickets.ts)

```ts
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '../src/generated/prisma/client.js';
const prisma = new PrismaClient({
  adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }, { schema: 'ctd_config' }),
});
```
