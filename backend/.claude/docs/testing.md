# Tests

- Unit tests (11 files, 90 tests, no DB needed): `tickets.service` (pagination/filter building, summary zero-fill, assignee defaults and AGENT limits, tenant-from-project, unknown/inactive references, Closed stamps / reopen clears `closed_at`, date order); `ticket-lookups.service` (case-insensitive duplicate names, rename to own name, delete refused while in use); `app.controller` (root info, docs link on/off by `SWAGGER_ENABLED`/`NODE_ENV`); `health.controller` (`/health` up and down, `/ready` never touches the DB, with terminus's mongo-then-SQL ping mocked); `prisma.service` (mocked `ConfigService`); `users.controller` and `users.service` (mocked Prisma: hashing, role_id conversion, password omitted, 404/409 mapping, and every role-escalation rule for ADMIN, SUPER_ADMIN and self-actions); `auth.service` (login success plus the 4 failure cases with the same error, changePassword); `auth.guard` (public routes, missing, forged and inactive cases, user attached); `roles.guard`; `parse-bigint.pipe`.
- In tests, `vi` and `describe`/`it`/`expect` are globals. Mock collaborators with `{ provide: X, useValue: {...} }`.
- e2e test: `test/app.e2e-spec.ts` boots the full `AppModule` and checks, without a token: `GET /` returns the info links, `GET /health` reports the real DB as up, and `GET /ready` returns ok. It needs a reachable DB and env vars (`DATABASE_URL`, `JWT_SECRET`), because PrismaService connects on init and JwtModule validates the secret.
