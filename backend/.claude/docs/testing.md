# Tests

- Unit tests (14 files, 151 tests, no DB needed): `permissions` (registry: modules register keys with descriptions, same key twice with a different description throws, malformed keys rejected; `*` expansion and whole-entry only; keys the code doesn't define grant nothing; **the real seed data** only grants defined keys, nests strictly and keeps each role's access); `permissions.service` (sync adds missing keys with code descriptions, fills empty descriptions but keeps edited ones, marks undefined keys obsolete without deleting, restores returning keys, no-op when in sync; catalogue listing; 404 on unknown key); `roles.service` (grant rows written sorted, unknown/obsolete keys rejected, grant only what you have, `*` only from a `*` holder, no modifying roles above you, replace/grant/revoke incl. idempotency, no removing `roles.manage` (or `*`) from your own role, no deleting your own role, delete refused while users have it, duplicate names); `permissions.guard` (all required permissions needed); `tickets.service` (pagination/filter building, summary zero-fill, assignee defaults and AGENT limits, tenant-from-project, unknown/inactive references, Closed stamps / reopen clears `closed_at`, date order); `ticket-lookups.service` (case-insensitive duplicate names, rename to own name, delete refused while in use); `app.controller` (root info, docs link on/off by `SWAGGER_ENABLED`/`NODE_ENV`); `health.controller` (`/health` up and down, `/ready` never touches the DB, with terminus's mongo-then-SQL ping mocked); `prisma.service` (mocked `ConfigService`); `users.controller` and `users.service` (mocked Prisma: hashing, role_id conversion, password omitted, 404/409 mapping, and every escalation rule for ADMIN, SUPER_ADMIN and self-actions, plus custom roles below/not below an ADMIN and roles with only unknown permissions); `auth.service` (login success plus the 4 failure cases with the same error, changePassword); `auth.guard` (public routes, missing, forged and inactive cases, user attached); `parse-bigint.pipe`.
- Tests that need roles use `test/helpers/seeded-roles.ts` (`seededKeys(name)`, `seededPermissions(name)`), which reads `prisma/seed-data/user_role.json` and registers every module's permissions. In tests, `vi` and `describe`/`it`/`expect` are globals. Mock collaborators with `{ provide: X, useValue: {...} }`.
- e2e test: `test/app.e2e-spec.ts` boots the full `AppModule` and checks, without a token: `GET /` returns the info links, `GET /health` reports the real DB as up, and `GET /ready` returns ok. It needs a reachable DB and env vars (`DATABASE_URL`, `JWT_SECRET`), because PrismaService connects on init and JwtModule validates the secret.
