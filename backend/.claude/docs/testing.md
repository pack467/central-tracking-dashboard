- Tests that need roles use `test/helpers/seeded-roles.ts` (`seededKeys(name)`, `seededPermissions(name)`), which reads `prisma/seed-data/user_role.json` and registers every module's permissions. In tests, `vi` and `describe`/`it`/`expect` are globals. Mock collaborators with `{ provide: X, useValue: {...} }`.
- e2e tests (2 files, 11 tests) boot the full `AppModule` (middleware and guards included, but not `main.ts`: no ValidationPipe, CORS or global filter). They need a reachable DB and env vars (`DATABASE_URL`, `SESSION_SECRET`), because PrismaService connects on init and the session config refuses to load without a secret.
  - `test/app.e2e-spec.ts`, without logging in: `GET /` returns the info links, `GET /health` reports the real DB as up, `GET /ready` returns ok.
  - `test/auth-session.e2e-spec.ts`: creates a temporary VIEWER (deleted afterwards, sessions by cascade) and logs in from several "devices" (supertest agents keep cookies). It checks: wrong password → 401 with no cookie; login from another origin → 403; login sets an `HttpOnly; SameSite=Lax` `ctd.sid` and a readable `ctd.csrf` and returns the user and the token; the cookie alone authenticates; writes without/with a wrong `X-CSRF-Token` → 403; a password change logs out the other device and keeps this one (new id, same token); `GET /auth/sessions` hides the sid and `DELETE /auth/sessions/:id` logs out that device; logout-all leaves no rows. It uses 5 logins, exactly the per-minute limit: keep new login calls in a separate app instance (each has its own throttle counters).
